# 规约驱动修订记录

本次从用户意图「修复正确性、报告写实、老师直接打开可用」拆解为：覆盖率、词形、结构、数据保留、密钥保护、CSRF、接口状态、免安装交付与证据一致性。

验收先定义可判定边界，再实现并回归。关键实例：6 个复习目标词至少 5 个命中；takeover 不算 take；taken 单独出现可以命中 take；密钥长度异常不改文件；缺 CSRF 返回 403；另一个用户读文章返回 404；落库失败后旧文章仍存在；无 MySQL 的独立体验可载入固定示例。

使用 AI 辅助阅读、实现、测试设计和文档修订。当前记录不提供可核实的历史开发模型版本、审查轮数或提交编号，因此不作相关断言。运行模型由 app.deepseek.model 配置，当前别名 deepseek-chat；不能由此推断背后具体模型版本。

高风险边界：不使用作者 Key，不调用付费服务，不清空现有数据库、不终止无关进程。本次 MySQL 验证使用单独临时实例，与原业务库隔离。

自动化证据在 verification；人工浏览器检查的操作与结果在 acceptance；自动检查不能判断文章论证质量或翻译自然度，这些需要人工评测。

### UI 补充约束（2026-11-15）

普通操作以深青色强调，错误使用独立红色；保留既有路由、表单字段与数据隔离。阅读正文控制行宽与行距，译文以独立背景区分；答题结果必须有文字，不能只依靠颜色。验证失败不得自动重发原请求。浏览器表单可返回恢复 HTML，但 API 响应约定不变。采用共享 `refinements.css` 和 `ui.js`，不引入前端框架。
